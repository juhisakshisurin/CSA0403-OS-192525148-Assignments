ASSIGNMENT 5 - PART B - B2: DOCKER COMMANDS

1. Check Docker
docker --version
docker compose version
docker info

2. Build the exact assignment image
docker build -t result-portal .
docker image ls result-portal

3. Run and map host port 8000 to container port 8000
docker run -d --name result-portal-standalone \
  -p 8000:8000 --cpus="0.50" --memory="512m" result-portal

4. Test and prove the app is non-root
curl -i http://localhost:8000/
curl -i http://localhost:8000/healthz
docker ps
docker exec result-portal-standalone whoami
docker stats --no-stream result-portal-standalone

Expected whoami: portal

5. Inspect image size and layers
docker images result-portal
docker history result-portal

6. Start app + PostgreSQL using Compose and a persistent volume
cp .env.example .env
# Edit .env and change POSTGRES_PASSWORD before use.
docker compose up --build -d
docker compose ps
docker compose logs --tail=50
curl -i http://localhost:8000/
docker compose exec portal whoami
docker stats --no-stream

7. Demonstrate volume persistence
docker compose down
# IMPORTANT: Do not add -v; without -v the named database volume is retained.
docker compose up -d
docker compose exec db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c 'SELECT 1;'

8. Build alternative image variants for comparison
docker build -f Dockerfile.ubuntu -t result-portal:ubuntu .
docker build -f Dockerfile.multistage -t result-portal:multistage .
docker images result-portal

9. Compare image pull time on a target machine
# Record the image size from "docker images".
# Pull time depends on link speed, cache, registry and concurrent traffic.
time docker pull result-portal:latest

Approximate lower-bound transfer time (seconds):
image size in MB * 8 / available throughput in Mbps
Actual time is higher due to protocol overhead, decompression and layer checks.

10. Optional vulnerability/package scan (install Trivy separately if required)
trivy image --scanners vuln result-portal:latest
trivy image --scanners vuln result-portal:ubuntu

Record actual findings by severity and affected package. A vulnerability count is not identical to the total number of installed packages.

11. Clean up
docker rm -f result-portal-standalone
docker compose down
# To intentionally remove the persistent database volume as well:
# docker compose down -v
